## 发布操作

1. 更新当前交付状态，保留失败案例和明确限制。
2. 执行 `scripts/check-code.ps1 -IncludeWebUI -IncludeRagServices`；记录具体覆盖范围，不把旧缓存启动称为干净首启。
3. 用 `scripts/verify_source_delivery.py` 导出当前交付源码，检查清单不含账号、密钥、数据库、模型权重与生成 WebUI。
4. 审核待提交路径和许可证。只有收到提交、推送/发布指令后才执行对应 Git 操作。
5. 对确切提交从 GitHub 干净 clone 执行 `start.cmd`，验证首次管理员、上传检索、只读数据源和重启持久化。下载网络失败与功能失败分开记录。

发布时应把实验性能力、支持的平台、首次下载要求、受信任部署者边界和未验收集成写进 Release。不能用“开源”替代企业生产安全与业务质量验收。
