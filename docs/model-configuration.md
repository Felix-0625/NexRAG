# 主 Agent 模型配置

NexRAG 只有一个对话与工具推理循环。用户选择的是运行该循环的实际模型，数据库、知识库、技能与工具权限不会随模型切换扩大。前端通过内部兼容接口连接 NexRAG；它不再把 NexRAG 服务名称或 Open WebUI 助手预设列作可选模型。

## 页面操作

管理员在“工作空间 → 模型”，或“设置 → 管理员 → 模型”管理同一份列表：

1. 添加显示名称、厂商、实际模型 ID、API 地址和接口协议。
2. 远程模型填写相应 API 密钥，本地免密服务可留空。
3. 保存后点“测试”，执行一次真实函数调用检查。测试通过表示连通与基础工具调用兼容，不表示复杂业务分析准确。
4. 设置使用范围为“全体账号”或“指定账号”；指定范围支持搜索姓名、邮箱并勾选账号。员工只能选择已启用且分发给自己的模型。系统默认模型必须对全体账号可用，避免无法使用默认模型。
5. 可设置系统默认模型。员工已有的个人默认选择优先。停用会阻止新请求，历史对话保留；必须先更换默认模型，才能停用原默认模型。

普通员工可查看启用模型的名称、厂商和实际 ID，没有添加、编辑、设系统默认或测试权限，也不会获得接口地址和密钥。聊天模型选择器自身的“设为默认”是个人偏好，与管理员的系统默认不同。

模型使用范围与数据外发许可分别校验。移除账号后，列表即时过滤，旧会话的新请求被拒绝；Agent在每次模型请求前重新检查使用范围，不依赖页面缓存或过去的会话授权。

## 厂商和协议

| 厂商 | 可用接入方式 |
| --- | --- |
| Ollama、DeepSeek、自定义兼容服务 | OpenAI Chat Completions |
| OpenAI | Responses 或 Chat Completions |
| Anthropic / Claude | 原生 Messages |
| Google / Gemini | 原生 Gemini API |

模型 ID 须填写当前账户在厂商 API 中实际有权使用的名称，不从 ChatGPT/Codex 等产品显示名称推断。各接入方式使用 PydanticAI 原生模型适配器，参考其[官方模型与厂商文档](https://pydantic.dev/docs/ai/models/overview/)。厂商列表不是多个业务服务入口。

## 真实执行与兼容

- 服务端将所选模型传给同一 PydanticAI Agent 的本轮运行，保留规划、数据库、知识检索、授权工具、导出和校验逻辑。
- 数据库与知识库授权仍由服务端签名身份和权限工具执行，模型不能自选账号或扩大范围。
- 主 Agent 以外的 Embedding、稀疏检索和重排保持现有配置；本轮没有添加服务子 Agent，也没有把这些专用模型放入聊天选择器。
- 旧请求中的 `NexRAG` 别名在核心接口映射到当前系统默认模型；旧助手预设数据保留，但从新模型列表中隐藏。WebUI 内部仍解析旧预设供已有自动化调用，公开模型列表只包含真实模型。历史会话选择的旧预设不再出现在新选择器，需要选择一个现有模型继续。
- Trace 的制品版本字段包含本轮模型配置 ID，可核对实际选择；该 ID 不含凭据。

## 凭据保存

模型配置在 `data/ops/ops.db` 中持久化，新增密钥使用 Fernet 加密；加密密钥派生自服务端 `NEXRAG_USER_JWT_SECRET`。此服务端密钥需随数据安全备份，替换后应重新填写模型凭据。管理员查询接口只返回“是否已有密钥”，不返回原文。更换厂商或 API 地址时必须重新填写或明确清除旧密钥，防止旧凭据被发往新地址。

首次使用会从现有 `LLM_*` 环境配置建立默认模型；该默认项最初引用环境密钥。保存的模型列表在后续启动时保留，不被环境默认值覆盖。删除模型不提供永久清除入口，使用停用管理可用性。

## 验证边界

新增回归覆盖管理员边界、密钥加密和保留、换地址不复用密钥、默认模型保护、停用拒绝、签名知识范围传递、实际模型进入共享工具循环，以及四类协议适配器构造。2026-11-01已使用短期凭据真实验证DeepSeek Flash/Pro的OpenAI和Anthropic兼容协议，以及公开合成知识问答、业务外发拒绝和旧会话撤权，结论见[逐项验收清单](acceptance/full-functional-acceptance.md)。临时密钥已清除，临时模型已停用；这不代表OpenAI、Anthropic或Google厂商已实际验收。

该轮修复了Anthropic SDK 2.x消息序列化兼容问题（升级PydanticAI至2.60），以及DeepSeek Flash别名的思考模式能力识别。思考模型不支持强制工具选择时，传输参数采用自动选择；业务证据完整性检查仍然保留。

本机前端验证记录见 [前端业务验收](frontend-acceptance.md)。

本轮两个本地模型均通过连接和基础工具调用检查，但复杂任务首轮仍出现漏查 SQL、错误统计和编造数据。Qwen 经明确追问后返回正确数据库记录；Hermes 实验项已停用。当前模型测试按钮验证协议和工具兼容性，不是回答正确性的评分器。
