## 验收发现及修复

- 自定义工具参数空字典导致 422：改为按真实函数 JSON Schema 注册本次请求专属工具；A 实际业务调用已通过。
- 业务视图已隔离，模型仍猜测部门 ID/状态导致空结果：提供服务端真实范围说明与同授权视图的有限诊断样本，不静默修改原始 SQL。A、B 实际正确查询通过。
- 报告链接被模型添加 `your-server` 域名：页面归一化为应用内产物路径；实际 CSV 下载通过。Agent 完整输出也校正已生成产物链接。
- 窄屏标题和业务范围重叠：移除导航负外边距；实际截图已确认分为两行。
- PydanticAI 流式输出不支持校验重试，且原自动化只等待入队便记录成功：先完成可重试校验后再通过 SSE 返回；自动化等待执行结束并检查内容。网页已经验证成功运行及撤权后的失败记录。代价是完整结果校验结束后才返回答案，不逐 Token 实时显示。
- 复杂请求调用多次检索后遗漏用户问题：Ollama 日志确认 4096 上下文窗口发生截断；启动器使用 16384，并压缩重复检索元数据，B 完整自然语言请求重跑通过。另外防止上游 RAG 模板遗漏原问题。
- 用量原先为零：从真实模型调用 usage 累加并通过最终 SSE 发送，网页显示 26.1k Token。此前没有上报用量的旧对话不追补。
- 临时对话原先仍进入核心追踪和记忆处理：跳过临时会话的追踪落库及后台记忆提取，增加回归覆盖；不删除之前验收留下的记录。
