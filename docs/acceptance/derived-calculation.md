# 派生优惠金额的证据闭环

2026-10-29 真实网页联合问答出现“已查到订单2000元和制度6%，但没有完成120元优惠计算”的部分完成结果。本次修复不把模型的心算加入数字白名单，也不把已有SQL/知识证据等同于全部任务完成。

- 仅移除行首 Markdown `1. ` / `2) ` 这样的列表标记。正文中的金额、订单编号和比例仍需本轮证据支持。
- 明确要求计算优惠或折后金额的任务增加 `discount_quote` 完成条件。仅查询折扣比例、上限仍是知识检索。没有获批计算器或未成功计算时，结果明确列出未完成的优惠步骤。
- 保留纯 `calculate_discount_quote` 的 Decimal API；Agent 的回调额外执行证据绑定。金额必须来自本轮真实SQL的金额列明细或 `SUM(源列)`，记录对应证据ID与列名；不接受SELECT常量、常量SUM、截断明细冒充合计。比例来自明确问题或已检索制度，有歧义必须选定证据。算出的120元优惠、1880元折后报价与2000元基数、6%比例一并绑定，不能用18000元基数的1080元优惠搭配2000元数据库总额。
- 重新检查输出中的优惠/折后字段含义，避免把已经存在的120和1880对调。校验覆盖常见中文字段、千位分隔和万/亿单位，仍不是任意自然语言的语义证明。
- 重试提示指向当前缺口，提醒复用已经成功的SQL/知识结果。相同SQL及相同行仅在保底展示层去重，原始工具调用仍保留审计。
- 发生输出重试耗尽、总时限等保底返回时，运行标记为 `partial`，`task_completed=0`，不会进入成功运行的个人记忆抽取；实验也读取此状态，`run_success` 不再把保底结果算作成功。缺少必要能力的保底仍作为未完成错误返回。
- 浏览器上传附件的动态指令明确使用 `search_knowledge_documents` 读取已授权索引，不能用 `inspect_local_file` 猜测宿主机路径。

离线回归执行真实校验函数及工具回调，覆盖列表编号误拦、漏计算、错基数/比例、常量SQL、歧义证据、授权撤回、字段互换、重复展示与partial状态。它不能替代主验收中的实际模型和网页复测；原失败会话应保留在验收记录中。

## 2026-10-30 定点复测

原始实模输出另暴露了两个确定性校验误判：`amount * 6 / 100` 中的除数被视为业务金额；“总金额与 KB1 的6%比例”这样的依据说明被误读为总金额字段。现已将前者绑定到实际计算器的公式、比例及结果后识别为数学表达式；后者只在金额标签紧接数值时视作字段。`折后额` 同时纳入净额语义检查。错误分母、错误比例、错误结果、独立的100元费用及折后额互换仍被拒绝。
