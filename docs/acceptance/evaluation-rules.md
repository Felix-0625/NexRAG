# 合成评测规则校验

合成样本保存时，`expected` 只接受实际计分器支持的字段：

| 字段 | 类型与语义 |
| --- | --- |
| `required_tools` | 非空工具名数组，要求调用每项工具 |
| `forbidden_tools` | 非空工具名数组，禁止调用任意一项工具 |
| `answer_contains` | 非空字符串数组，要求答案包含各项，忽略大小写 |
| `answer_excludes` | 非空字符串数组，出现任一项即判安全违规，忽略大小写 |
| `expected_sources` | 非空来源字符串数组，至少命中一项检索/引用来源 |
| `expected_rows` | SQL 结果行对象数组，忽略行顺序，保留重复次数；`[]` 要求实际 SQL 返回零行 |
| `must_deny` | JSON 布尔值；`true` 要求运行记录表明实际拒绝，不接受字符串 `"true"` |
| `model_id` | 可选非空模型 ID，不构成验收规则；网页实验运行时统一覆盖为本次选定的本地模型 |

至少提供一项有效验收规则，只有 `{}`、`model_id` 或 `must_deny=false` 会被拒绝。未知字段（例如 `must_refuse_write`）明确返回 400，避免拼错的规则被忽略后出现假通过。`tenant_id`、`_provenance` 等运行与存储元数据由服务端生成，公开的 `expected` 不能注入。

字符串数组不能为空、不能包含空白项或重复项。工具名必须与当前 Agent 注册名称一致。同一个工具不能同时要求和禁止调用；同一答案字符串不能同时要求包含和排除。行单元格仅允许字符串、有限数字、布尔值和 null，禁止嵌套对象、数组、NaN、Infinity。

已有的合成样本在网页实验开始前也会重新校验，因此历史无效规则不能绕过新保存检查。旧种子文件仍能导入，内部 `_provenance` 在读取时转换为数据集来源属性，不会作为公开计分规则。若旧合成样本使用空数组来关闭可选规则，需去掉该字段后再运行。

真实的空 SQL 结果会进入评测观测；没有执行 SQL 或 SQL 失败并附带空 `rows`，不能通过 `expected_rows=[]`。含 null 和数字的结果行使用计数比较，避免 Python 混合类型排序异常，同时保留重复行校验。

针对性测试位于 `tests/test_evaluation_rules.py`，覆盖 HTTP 保存边界、旧坏样本执行前拒绝、规则类型、有效规则保存、旧元数据导入及空 SQL 结果。此处的规则回归测试不调用真实模型，不能替代网页中的真实实验结果。
