# MCP 审批与执行边界

MCP 工具通过官方 SDK 的 Streamable HTTP 协议接入现有单 Agent 工具循环。没有新增第二个 Agent，不执行 stdio 命令、Python 插件或服务器返回的源码。

管理员先保存固定服务地址，再执行真实 `initialize` / `tools/list`，查看各个工具的描述和参数 schema，逐项确认只读用途并审批。精确能力 ID 是 `mcp:<server-id>:<tool-name>`，按现有账号 `allowed_tool_ids` 分发。MCP 服务声明的只读提示不能代替管理员对目标服务行为、凭据权限的确认；本实现只允许管理员确认的只读工具，不提供远程写操作审批流程。

审批绑定服务 revision，以及工具描述、输入/输出 schema、annotations 的 SHA256。配置保存会撤销旧审批；重新发现时变化的工具需要重新审批。每次实际调用重新获取工具列表核对哈希；本地撤销、服务配置变化或远端工具变化后，旧会话不能继续执行旧能力。

执行前和发送 `tools/call` 前都会刷新账号、知识库及业务权限。必须同时满足账号精确工具授权、本次全部可读资源的外部工具许可；secret 始终拒绝，即使服务是本机 loopback。初始权限不满足时，不建立 MCP 连接也不发送参数。服务发现只是管理员向固定服务查询工具定义，不会自动附带业务问题、聊天历史、私库正文或文件。

当前资源策略对全部可读知识库取保守交集。账号只要有一个禁止外部工具的可读资源，就不能把该会话数据发送给 MCP。公开合成数据的演示应使用只有公开资源的独立账号，或由资源所有者明确设置数据分级与工具外发许可。不能靠在聊天中声称“这是公开数据”扩大范围。

网络与凭据措施：

- 远程服务必须 HTTPS，TLS 验证始终开启；HTTP 仅接受明确的本机 loopback。DNS 解析结果固定到实际连接 IP，保留原 Host 和 TLS SNI；公网域名解析到内网、loopback 或链路本地地址会被拒绝。`localhost` 必须实际解析到 loopback。
- 禁止任何重定向，包括 SDK 默认可能跟随的同源 307/308；需要管理员直接填写最终服务地址。关闭环境代理，禁止压缩响应，防止压缩体绕过响应大小限制。
- 单次整体 deadline 为 30 秒，连接超时 5 秒；工具参数最多 16 KiB，返回结果最多 64 KiB，会话 HTTP 响应累计最多 256 KiB；工具发现有数量和分页上限。
- Token 使用服务端 JWT 密钥派生的独立 Fernet 密钥加密存储，列表仅显示是否配置。更换地址时必须重新填写凭据或明确清除，避免旧凭据被转发给新目标。
- 参数按已审批 JSON Schema 校验，禁止外部 schema 引用和参数到 HTTP 请求头的映射。审计保留最近 200 次配置、审批、撤销和调用的动作/账号ID/工具ID/状态/时间，不保存参数、结果正文或凭据。

没有正确安装官方 `mcp>=2.2,<3` 及其依赖时，接口明确报告当前不可用，不伪造工具执行成功。实际锁定安装版本以根 `uv.lock` 为准；本轮使用独立冻结环境中的官方 MCP 2.3.0 验证。

`tests/test_mcp_registry.py` 使用独立 SQLite。它包含官方客户端与官方 `MCPServer` 之间真实的 Streamable HTTP 初始化、工具发现、调用和远端工具变更检查；HTTP 通过进程内 ASGI 传输，没有访问外网或读取员工数据。另有拒绝、撤销、schema、DNS、重定向、大小、加密和 API 状态码回归。这些测试不是浏览器验收，也不能证明某个第三方服务的实际业务行为；真实网页操作的证据应另行记录。
