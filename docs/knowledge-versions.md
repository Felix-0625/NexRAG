# 知识库版本维护与恢复

所有者在知识库的“版本与更新记录”中发布版本、下载快照或恢复历史版本。文件上传和内容编辑也自动记录更新。恢复前自动存档当前工作内容，恢复结果作为一个新版本保留；以前的版本不会被覆盖。

恢复包含知识库名称、说明和快照中的全部文件内容。旧版快照未记录目录布局，因此文件恢复到知识库根目录。历史版本不携带授权：恢复始终保留当前所有者、账号与分组授权、企业全员分发、内容分级和外发限制。只有所有者可以执行恢复，获授权员工可查看版本和下载快照。私人库的内容及历史不会因访问者是管理员而开放。

## 发布一致性

恢复先逐一验证归档对象的 SHA256 和大小，再复制文件并通过既有本机摄入服务完成解析、Child Dense/BM42 索引和 Parent Payload 写入。文件使用新 ID，避免覆盖同一原文件在其他知识库中的副本。全部成功后，一个 WebUI 数据库事务同时替换文件关联、当前检索命名空间及恢复审计记录。任一步失败都不发布新命名空间。

命名空间仍是同一个 Qdrant 集合内的 Payload 范围，不新增独立数据库、索引服务或父块存储。隔离构建后切换读取目标的设计参考 [Qdrant 的索引切换说明](https://qdrant.tech/documentation/manage-data/collections/#collection-aliases)；本项目切换的是数据库内的逻辑范围指针，并未调用 Qdrant 集合别名 API。

上传、编辑、删除、版本发布和恢复共用本机跨进程写入协调，覆盖完整 ASGI 请求以及响应后台任务。上传的索引写入与最终文件关联之间不会插入恢复发布。读取不等待这把写锁，继续使用已发布版本。协调使用 [filelock](https://py-filelock.readthedocs.io/en/latest/)，锁文件位于当前 DATA_DIR，不需要外部组件。

对话的知识范围和内容分级由当前账号授权重新签名，指向当前发布的命名空间。发布过程中仍在运行的旧轮次若发现范围变化会停止沿用旧上下文；新轮次重新检索当前版本。后续文件维护也写入当前命名空间。

## 验收边界

真实 SQLite 事务回归覆盖发布成功、索引失败、提交失败及所有者边界；实际 ASGI 后台任务回归覆盖并发上传与恢复的先后顺序，读取保持可用。网页验收结论见 [逐项验收清单](acceptance/full-functional-acceptance.md)。这些证据不等于高并发负载或长时间稳定性验证。

未发布的临时文件和向量在失败时清理。进程被强制终止时可能留下不可达的暂存对象；当前不自动清扫这些对象，以免误删历史或在读内容。
